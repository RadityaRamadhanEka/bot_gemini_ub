**4. DEMO GEMINI**  
- **Prompt lengkap yang siap ditempel**:  
  `"Ajari saya query SQL dasar untuk menampilkan transaksi menu 'Nasi Ayam' dari tabel transaksi. Jelaskan setiap baris query dengan bahasa sehari-hari, gunakan hanya SELECT, FROM, dan WHERE, lalu berikan satu latihan serupa tanpa langsung memberi jawabannya."`  
- **Contoh hasil (ilustrasi yang perlu dibuat ulang di Gemini)**:  
  ```text
  SELECT * FROM transaksi WHERE menu = 'Nasi Ayam';
  - SELECT: "Minta petugas menampilkan semua data yang diperlukan"
  - FROM: "Sumber data (tabel transaksi)"
  - WHERE: "Kriteria pencarian (menu = 'Nasi Ayam')"
  Latihan: "Coba cari transaksi menu 'Kopi' dengan query yang sama."
  ```  
  *Catatan: Hasil ini adalah ilustrasi untuk produksi—perlu diverifikasi di Gemini sebelum syuting.*

**7. Checklist produksi**  
- ✅ Properti/asset: Tabel transaksi sintetis (fiktif), buku kas kantin visual, layar komputer untuk query  
- ✅ Keterbacaan teks di layar: Font size 24px (minimal untuk 9:16), kontras tinggi  
- ✅ Safe area vertikal: 10% di tepi atas/bawah, 5% di tepi samping  
- ✅ Perlindungan data pribadi: Data transaksi fiktif (tidak ada NIM, no HP, atau data nyata)  
- ✅ Tidak ada klaim berlebihan: Fokus pada konsep dasar, tidak menyatakan "pasti" atau "tanpa belajar"

### Saran Pengembangan (Opsional)  
1. **Tambahkan visualisasi data sintetis**: Gunakan tabel transaksi fiktif dengan 3-5 baris data (misal: "Tanggal", "Menu", "Jumlah") untuk memperjelas contoh query tanpa mengganggu alur Reel.  
2. **Optimalkan waktu adegan 25-35s**: Jika waktu syuting terbatas, kurangi teks overlay menjadi *"Coba cari menu favoritmu di komentar!"* untuk mempercepat transisi ke CTA.  
3. **Verifikasi hasil Gemini**: Pastikan contoh query dan latihan di *Demo Gemini* sesuai dengan data sintetis yang digunakan (misal: jangan menggunakan "Kopi" jika data fiktif hanya berisi "Nasi Ayam").  

*Catatan: Semua saran di atas tidak mengubah pesan utama atau angle konten, hanya meningkatkan kejelasan produksi.*
